# フィードバック設計 — 原理（蒸留済み）

最終更新: 2026-09-29

## 操作単位の即時 FB

- 「確定」ボタンを挟まず、**操作直後**（1 マス入力、1 トグル、1 スクラブ刻み）に音・粒子・触覚を返す
- 正解/不正解の差は **色・短音・小さなモーション** に留め、画面遷移は伴わせない
- 出典: [dopa-drill](../../references/2026-09-27-dopa-drill.md), [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## 非同期 CTA は同一 UI 上で状態遷移

- フォーム送信・API 呼び出しは **idle → loading → success / error** を 1 ボタン（または連続モーフ）で見せる
- 成功/失敗後は **自動復帰** または次アクションへ誘導し、ユーザーが状態を覚えなくてよいようにする
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## 完了・失敗・空は統一演出

- フロー終端（成功/失敗/データなし）は **同じ画面骨格**（アイコン・見出し・CTA 配置）で揃える
- 空状態も「エラー」ではなく **次の行動** を示すコピーと CTA を置く
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## 読込中は形を保つ（スケルトン）

- リスト・カード・タイルは **実コンテンツと同じ骨格** のプレースホルダを見せ、レイアウトシフトを防ぐ
- スピナー単体より、**何が載るか** が分かる形を優先する
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## 軽量 FB は非ブロッキング

- 保存完了・コピー・軽微な成功は **トースト** 等、操作を遮らない一瞬の FB に留める
- モーダルや全画面遷移は **判断を要する結果** にだけ使う
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## リアクションは触覚付きトグル

- いいね・保存・評価など **反復トグル** は、色の flood + 短いハプティックで ON/OFF を体感させる
- スクラブ操作（リング・チャート）は **刻みごとに触覚** を返し、連続操作にリズムを付ける
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## AI 待機は「考えている」状態を見せる

- 応答生成中は **思考プレースホルダ**（ドット、経過秒、オーブ）で空白を埋める
- ストリーミング返答は **トークン単位** で追記し、一括表示より「届いている感」を出す
- Reduce Motion 時はアニメを抑え、**テキスト/経過表示** は維持する
- 出典: [SwiftPieces](../../references/2026-09-27-swiftpieces.md)

## 得点と快感は別トラック

- スコア・正解率とは別に、**ログ表示・コンボ倍率** 等の「気持ちよさ専用」FB を載せられる
- 学習/習慣系では快感トラックを **演出強度** と連動させ、得点の公平性は崩さない
- 出典: [dopa-drill](../../references/2026-09-27-dopa-drill.md)

## 演出強度は音も連動

- セッション内エスカレーションに合わせ、**BGM テンポ・転調** 等も段階的に上げる
- 視覚だけ盛るより、**聴覚リズム** で「クライマックス感」を補強する（Reduce Motion / 音量 OFF でも得点は同じ）
- 出典: [dopa-drill](../../references/2026-09-27-dopa-drill.md)

## 快感は「届く前」の予測に置く

- 報酬 UI の峰值だけでなく、**次の FB までの間隔・予測可能なリズム** を設計する
- 供給サイクルを短くするとテンポが上がり、間隔を空けると期待が溜まる — セッション目的に合わせて選ぶ
- 出典: [watanabe-manga-pacing](../../references/2026-04-07-watanabe-manga-pacing-dopamine.md), [idesho-dopamine-prediction](../../references/2026-08-24-idesho-dopamine-prediction-vs-reward.md)

## 可変比率強化は領域で使い分ける

- 報酬の **タイミング・内容がランダム** だと習慣化は強いが、**不透明・不公平感** を招きやすい
- 教育・習慣・子供向けは **確定報酬・条件明示**（progression）を優先 — 課金ゲーム以外ではランダム箱を避ける
- ランダム FB を使う場合も **感情体力**（habit）と整合 — 当たらないたびの失望・損失表示を避ける
- 出典: [irresistible](../../references/2026-09-29-irresistible.md)
